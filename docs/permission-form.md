## What the check-up does

The check-up only reads what each website already sends to every visitor. For each website, the checker:

- Makes one normal page request, the same as opening the home page in a browser.
- Makes one secure-connection check, the same step a browser takes before it shows the padlock.
- Reads the security settings the site sends with its pages, its certificate (who issued it and when it expires), its encryption version, and any software version numbers the server shows.

For a code folder or repository, the checker reads the files for passwords, keys and tokens that should not be there. It also checks for software packages with known harmful versions.

The client receives a written report in plain language, with what was found, why it matters and how to fix it.

## What the check-up will never do

- Log in to anything, or guess passwords.
- Try to break in, or use any weakness it finds.
- Send heavy traffic or load tests. The website will not slow down.
- Change anything on the website, server, accounts or code.
- Open private pages, admin areas or customer data.
- Check anything that is not listed under "What will be checked".

## Privacy of the results

The results belong to the client and go only to the people named on this form.

- The checker never shares, publishes or shows the results to anyone else without the client's written permission.
- If a password or key is found, the report shows only where it is and a masked hint, such as ****MPLE. The full value is never copied. The client should change any key that is found.
- Any copy of the client's code is deleted as soon as the check-up is finished.
- Results are deleted 30 days after the report is delivered. With monthly re-checks, the latest results are kept so each month can be compared with the last.

## Limits and fee

A clean report means no problems were found in the checks listed above. It does not mean the website is fully secure.

- Software versions are read from what the server says about itself, which can be hidden or wrong. Those results are marked "possible" in the report.
- The checker gives advice. The client, or the client's web developer, decides what to change and makes the changes.
- The checker's total responsibility is limited to the fee paid for the check-up.
